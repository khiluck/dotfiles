# facecam — виртуальная камера с 3D-моделью и настоящими глазами и ртом

Своя софтина: берёт настоящую камеру, рисует вместо головы 3D-модель, которая
поворачивается вместе с твоей головой, но **глаза и рот остаются настоящими** —
вырезаются из живого видео и кладутся поверх модели. Результат отдаётся как
обычная веб-камера, которую видят Teams, браузер и что угодно ещё.

Запуск — по требованию (хоткей/скрипт), не при загрузке системы.

## Почему именно так

Разбирали три разных эффекта, это третий:

| | что это | сложность |
|---|---|---|
| Полная замена (VTuber) | тебя не видно, вместо тебя персонаж | делается готовым софтом |
| AR-маска (Snapchat) | 3D поверх настоящего лица, с перспективой и окклюзией | тяжело, готового под Linux нет |
| **Наш вариант** | 3D-модель + настоящие глаза и рот поверх неё | **проще AR-маски** |

Наш вариант проще AR-маски, потому что композитинг тут **плоский**: куски живого
видео кладутся поверх уже отрендеренной 2D-картинки. Никакой трёхмерной
математики при наложении, никакой окклюзии.

Два следствия, которые срезали половину работы:

1. **Модели не нужна мимика.** Ни блендшейпов, ни лицевого рига — вся
   выразительность приходит из настоящего видео. От трекера нужна только поза
   головы.
2. **Кривизна — часть эстетики.** «Приклеенность» кусков здесь не баг, а смысл.
   Не надо добиваться бесшовности, а это самое дорогое требование.

## Архитектура

Один процесс на Python. Ни браузера, ни OBS, ни захвата окна — кадры пишутся
прямо в устройство.

```
/dev/video0 ──► [1 трекер: поза головы + контуры глаз и рта]
                        │
                        ├──► [2 рендер 3D-модели по позе головы]
                        │              │
                        └──────────────┴──► [3 композит трёх слоёв]
                                                      │
                                          /dev/video10 (v4l2loopback)
                                                      │
                                          Teams / браузер / mpv
```

Слои композита снизу вверх:

1. **фон** — однотонный, картинка, размытый настоящий кадр или сам кадр;
2. **3D-модель**, посаженная так, чтобы её глазницы легли на твои глаза;
3. **настоящие глаза и рот**, вырезанные из живого кадра.

Вырезка по умолчанию обрезается силуэтом модели (`clip`): иначе рот, не попавший
на модель, повисает на фоне сам по себе.

### Почему не браузер

Первая прикидка была на Chromium + MediaPipe JS + `three-vrm` — ради готового
VRM-рига с блендшейпами. Но как только выяснилось, что **мимика не нужна**,
единственный плюс браузера испарился, а минус остался: из браузера картинку
всё равно пришлось бы выковыривать захватом окна (`x11grab`) или через OBS.
Python-процесс пишет в `v4l2loopback` напрямую.

### Развилка про одну камеру

UVC-устройство отдаёт поток **одному** клиенту. Если бы трекер, рендер и
композитор были разными процессами, они бы дрались за `/dev/video0`.
У нас всё в одном процессе — камера открывается один раз, проблема снята.
Если когда-нибудь понадобится разветвление, решается через `v4l2loopback`
(он, в отличие от железки, отдаёт поток нескольким читателям).

### Ловушка с Python 3.14

В системе Python **3.14.7** — очень свежий. Исторически MediaPipe собирался под
конкретный ABI CPython и за новыми версиями не поспевал; это был главный риск
всей затеи. Но **MediaPipe 1.0.1 приехал колесом `py3-none-manylinux`**, то есть
без привязки к ABI, и на 3.14 импортируется нормально. Проверено.

Если это когда-нибудь сломается — запасной путь есть: `python312` в AUR или
трекер OpenSeeFace на `onnxruntime` (он даёт 68 точек и позу без MediaPipe).

Зависимости стоят в venv внутри проекта, систему не трогаем:

```bash
python -m venv venv && ./venv/bin/pip install -r requirements.txt
```

## Открытые вопросы

1. **Какая 3D-модель.** От неё зависит весь вид. Пока не выбрана — этап 3
   делается на заглушке, модель меняется потом.
2. **Ширина вырезки.** Контур глаза от MediaPipe обтягивает саму глазную щель.
   Для эффекта, похоже, нужна область пошире — глазница целиком. Решается
   расширением многоугольника (`cv2.dilate` по маске), параметр подберём на
   картинке.
3. **Брови.** Контуры бровей приходят как 4 незамкнутых куска, а не цикл.
   Если захотим оставить брови настоящими — их надо будет собирать иначе.

## Как это запускать

```bash
cd ~/Work/dotfiles/facecam

# картошка на размытой комнате — основной режим
./venv/bin/python facecam.py avatar --model models/Potato.glb --background blur:61

# картошка в пустоте
./venv/bin/python facecam.py avatar --model models/Potato.glb --background '#1e3a2f'

# обезьяна поверх настоящей комнаты
./venv/bin/python facecam.py avatar --model models/Suzanne.gltf

./venv/bin/python facecam.py passthrough     # видео как есть (проверка тракта)
./venv/bin/python facecam.py track           # разметка лица поверх видео
```

Модуль ядра подхватывается сам (`vcam.ensure_module`, через sudo), если
`/dev/video10` ещё нет. Вручную:

```bash
sudo modprobe v4l2loopback devices=1 video_nr=10 card_label=facecam exclusive_caps=1
```

`exclusive_caps=1` **обязателен**: без него устройство объявляет разом OUTPUT и
CAPTURE, и Chromium (а значит и Teams на Electron) такую камеру игнорирует.

Полезное следствие: с `exclusive_caps=1` устройство видно как камера только
пока facecam запущен. В списке камер Teams фантомной записи не болтается.

### Ловушка с правами

После `modprobe` udev назначает группу `video` не мгновенно. Секунду устройство
существует как `root:root`, и открыть его нельзя. Лечится `udevadm settle`
(уже вшито) либо `sudo udevadm trigger --subsystem-match=video4linux`.

## Размер вырезки

Расширение контура задаётся **раздельно для глаз и губ**, и оба значения
отрицательные. Одним числом их не настроить, потому что контуры MediaPipe
означают разное:

* **глаз** — линия век, то есть естественное раскрытие глаза. Берётся как
  есть (0): это ровно то, что нужно.
* **губы** — кайма губ. Сверху в заливку попадает тёмная полоска усов, поэтому
  контур тоже поджимается. Зубы при этом не теряются: они внутри контура.

Замеренные на глаз значения:

**Эти числа скомпенсированы под растушёвку и ходят с ней парой.**

Растушёвка почти не меняет геометрию: площадь маски по уровню 50% падает всего
на 2–3%. Но она съедает **непрозрачную сердцевину** — при `feather=6` у глаза
в полную силу видно лишь 36% исходной площади, у губ 52%, остальное подмешано
к модели и выглядит блёкло. Именно поэтому после введения мягких краёв
показалось, что зоны стали меньше: геометрически нет, по насыщенности — втрое.

Непрозрачная площадь ГЛАЗА в % от неразмытой, по замеру на кадре анфас:

| растушёвка \ захват | +0 | +1 | +2 | +3 | +4 | +5 |
|---|---|---|---|---|---|---|
| 2 | 71% | 86% | 107% | 128% | 156% | 181% |
| 3 | 64% | 80% | 99% | 120% | 147% | 172% |
| **4** | 56% | 70% | 89% | **110%** | 135% | 160% |
| 5 | 51% | 65% | 82% | 103% | 128% | 151% |
| 6 | 43% | 55% | 73% | 92% | 117% | 138% |

По этой таблице и подбирается пара. Текущая — растушёвка **4**, захват **+3**.

Отсюда умолчание для глаз: **+3** при растушёвке 4 — непрозрачность 110%.

**У губ компенсация не применяется** — там ограничивает не растушёвка, а
щетина, см. ниже.

### Контур губ у MediaPipe шире настоящих губ

Проверено на увеличенном кадре с нарисованным контуром: внешний контур `LIPS`
сверху заходит в усы, снизу — в бороду под нижней губой, по краям вылезает за
уголки рта. Это не погрешность трекера, а то, как размечена модель: «губы» там
означают губы плюс полоска кожи вокруг.

Поэтому при захвате 0 по кайме идёт серая крапчатая полоска щетины. Замер по
увеличенным кадрам:

| захват губ | что видно |
|---|---|
| +1 | крапчатая полоска щетины сверху и снизу |
| 0 | то же, слабее |
| −1 | ещё слабее |
| **−2 (по умолчанию)** | **чисто, губа полная** |
| −3 и ниже | чисто, но губа худеет |

Если сменишь камеру или сбреешь бороду, это значение надо пересмотреть: оно
подобрано под щетину, а не под геометрию.

Потолки, за которые лезть не стоит:

| область | предел | что случается |
|---|---|---|
| глаза | от +7 | в вырезку входит кожа века, получается заплатка |
| глаза | до −2 | глаз подрезается по радужке |
| губы | от +3 | сверху проступает тёмная полоска усов |

**Меняешь `--feather` — пересматривай и захват.**

Подбирать эти значения надо по кадру **анфас с открытыми глазами**. На кадрах
с наклонённой или отвёрнутой головой контур глаза вытянут перспективой, и
выбор получается неверным — я на этом споткнулся дважды.

## Дырка во рту (закрыто)

При открытом рте вместо зубов была видна модель. Причина не в маске и не в
контурах, а в `cv2.fillPoly`: если передать ему **список** контуров, он заливает
по правилу чётности, и вложенный контур **вычитается**. У губ контура два —
внешний и внутренний, — поэтому в маске появлялась дырка ровно по отверстию рта.

Проверено на двух вложенных квадратах: одним вызовом заливается 5720 px с
пустотой в центре, по одному в цикле — 6561 px сплошняком.

Сколько терялось на настоящих губах:

| раскрытие рта | площадь маски | заливалось | терялось |
|---|---|---|---|
| закрытый | 3521 | 1836 | 1685 px (48%) |
| ×3 | 6710 | 1566 | 5144 px (77%) |
| ×6 | 13121 | 4685 | 8436 px (64%) |

При закрытом рте дырка была тонкой полоской между губами и в глаза не
бросалась, поэтому баг дожил до первого открытого рта.

**Правило:** контуры области заливать ТОЛЬКО по одному
(`compose._fill`). Любая область с вложенным контуром иначе получит дырку.

## Увеличение вырезки

Аккуратный глаз объективно мал и на крупной модели читается точкой. Поэтому
вырезка глаз увеличивается относительно **собственного центра** каждого глаза:
переносятся сами пиксели, а не только маска. По умолчанию 1.18 — заметно, но
без выпученности.

Рот намеренно не увеличивается (`ZOOM["lips"] = 1.0`): он и так выразителен, а
увеличение сдвинуло бы его относительно положения на модели.

## Тёмная обводка по краю вырезки (закрыто)

По краю глаз и губ шла тёмно-коричневая линия — чёткая граница вместо мягкого
перехода в модель.

Причина: растушёвывалась **маска**, но не слой с пикселями. Настоящие пиксели
копировались строго по жёсткой маске, поэтому в полосе, где маска уже не 0, но
ещё не 255, слой оставался **чёрным**. Это чёрное подмешивалось к модели и
давало тёмный кант. Замер по одному глазу: в полосе растушёвки 53% пикселей
были чёрными, средняя яркость 20.9 против 38.9 внутри маски.

Лечится тем, что пиксели кладутся ШИРЕ маски — на радиус растушёвки
(`cv2.dilate` перед копированием). После правки чёрных в полосе 0%, яркость
45.3 — это кожа вокруг глаза, как и должно быть.

**Правило:** растушёвывая маску, всегда проверяй, что под полосой растушёвки
есть настоящие пиксели. Иначе туда подмешается фон слоя.

### Про величину растушёвки

| значение | как выглядит |
|---|---|
| 2 | край уже почти очерчен |
| 3 | чётко, переход заметен |
| **4 (по умолчанию)** | **края мягкие, черты не размазаны** |
| 6 | мягко, но эффект уже «замыленный» |
| 10 | глаз начинает съедаться |
| 16 | ядро сопоставимо с размером глаза: маска не доходит до 255, сквозь глаз просвечивает модель |

Глаз мал, поэтому растушёвка бьёт по нему сильнее, чем по губам. Выше 10 не
стоит.

**Обратная сторона малых значений:** размытие заодно прятало фактуру по кайме
губ — щетину, растущую вплотную к ним. Чем меньше растушёвка, тем эта
зернистость заметнее, и поджатием губ её не убрать: она сидит на самой губе, а
не вокруг. Проверено на увеличенных кадрах — при растушёвке 4 значения −2, −3
и −4 по зерну почти не отличаются, губа только худеет.

## Картошка

Готовую модель картошки не брал: у случайных моделей из интернета мутная
лицензия, а картошка — это бугристый эллипсоид, который проще сгенерировать.
Своя генерация решает разом и лицензию, и главное: **у картошки нет глаз**,
поэтому якоря не ищутся, а назначаются — генератор ставит их сам.

```bash
# текущая: овальная стоя, слегка неправильная
./venv/bin/python tools/make_potato.py --axes 0.75,1.0,0.80 --amp 0.06 --seed 3

./venv/bin/python tools/make_potato.py --seed 42                   # другая случайная
./venv/bin/python tools/make_potato.py --eye-dx 0.35 --eye-y 0.25  # глаза выше и шире
```

Форма — икосфера, растянутая в эллипсоид и смещённая вдоль нормалей суммой
синусоид разных частот. Настоящий шум Перлина не понадобился: на глаз разницы
нет, а зависимости меньше. Текстура рисуется тут же — коричневая кожура с
разводами и тёмными глазками.

### Что задаёт форму

| ключ | что делает |
|---|---|
| `--axes X,Y,Z` | полуоси эллипсоида, **Y — высота**. Первая версия была `1.0,0.78,0.82`, то есть шире, чем выше — получался бесформенный блин. Сейчас `0.75,1.0,0.80`: картошка стоя |
| `--amp` | высота бугров. 0.03 — гладкое яйцо, 0.06 — картофелина, 0.13 и выше — корявый комок |
| `--bumps` | сколько волн задают рельеф |
| `--seed` | другая случайная картошка при тех же параметрах |

Подбиралось перебором: при `amp` от 0.13 форма читается как «бесформенная
хрень», при 0.03 — как яйцо. 0.06 — та самая середина.

Генератор кладёт в файл якорей и свой `margin` (1.35): у высокой картошки он
другой, чем у плоской.

## Как поменять модель

Нужны две вещи: файл модели и её **якоря**.

### 1. Файл модели

Формат — **glTF** (`.gltf` + `.bin` + текстуры, либо `.glb`). Кладётся в
`models/`. Требования: одна меш-группа, есть нормали и UV, есть базовая
текстура. Анимация и скелет не нужны и игнорируются — модель только жёстко
поворачивается.

Проверить, что модель читается:

```bash
./venv/bin/python tools/find_anchors.py models/Твоя.gltf
```

Где брать бесплатные: [Khronos glTF-Sample-Assets](https://github.com/KhronosGroup/glTF-Sample-Assets)
(много CC0), Sketchfab с фильтром по лицензии, VRoid Hub. **Лицензию смотреть
обязательно**: например, у популярного `DamagedHelmet` одна из составляющих под
CC-BY-**NC**, то есть в рабочем созвоне использовать нельзя. У взятой Suzanne —
CC0, ограничений нет (`models/Suzanne.LICENSE.md`).

### 2. Якоря

Якорь — центр глаза модели в её собственных координатах. По двум якорям facecam
сажает модель так, чтобы её глазницы совпали с твоими глазами. **Это ключевой
момент эффекта.** Первая версия сажала модель по габариту лица — получались два
набора глаз рядом, а не «мои глаза на модели».

Если глаза модели выделены цветом в текстуре — находятся автоматически:

```bash
./venv/bin/python tools/find_anchors.py models/Твоя.gltf \
    --color 240,224,144 --tol 60 --write
```

Иначе — снять на глаз по проекциям:

```bash
./venv/bin/python tools/find_anchors.py models/Твоя.gltf --render /tmp/views.png
```

и вписать числа руками в `models/Твоя.anchors.json`:

```json
{
  "model": "Твоя.gltf",
  "eye_x_pos": [0.380, 0.236, 0.801],
  "eye_x_neg": [-0.321, 0.218, 0.810]
}
```

`eye_x_pos` — глаз со стороны положительного X, `eye_x_neg` — противоположный.
Порядок важен: перепутаешь — модель встанет задом наперёд.

### 3. Подгонка

Пропорции модели не обязаны совпадать с человеческими. Suzanne повезло:
отношение межглазного расстояния к высоте головы у неё 0.36, у человека ≈0.35,
поэтому она садится почти сама. Модель с другими пропорциями подгоняется
`--margin` (накрыть больше лица) и, если понадобится, `dx/dy` в `compose()`.

## Как сделать свою модель в Blender

```bash
sudo pacman -S blender
```

glTF Blender экспортирует из коробки, плагинов не нужно.

**Здесь проще, чем в обычном 3D:** наша модель не анимируется — ни скелета, ни
развесовки, ни блендшейпов. Это ровно та часть, на которой обычно и ломаются.
Остаётся слепить форму, развернуть UV, покрасить, экспортировать.

1. **Форма.** `Shift+A` → Mesh → UV Sphere, дальше вкладка **Sculpting**:
   кисти Draw, Grab, Smooth — мнёшь как пластилин.
2. **UV.** В режиме правки `U` → Smart UV Project. Для органики автоматики
   достаточно.
3. **Цвет.** Вкладка **Texture Paint** — красишь прямо по модели. Если вместо
   этого использовать процедурные ноды, их надо **запечь** в картинку
   (Render → Bake → Base Color), иначе в glTF они не уедут.
4. **Экспорт.** File → Export → glTF 2.0, формат **glTF Binary (.glb)** —
   один файл со всем внутри.
5. **Якоря.** `tools/find_anchors.py --render /tmp/views.png`, смотришь
   проекции, вписываешь координаты глаз в `.anchors.json` (см. раздел выше).

### Ловушка с осями

**Blender считает верхом ось Z, а glTF — ось Y.** Экспортёр пересчитывает это
сам, но следствие неочевидное:

> Модель должна смотреть в камеру **вида спереди** (Numpad 1), а макушка —
> вверх по Blender-овскому Z.

Тогда после экспорта она встанет лицом в +Z и макушкой в +Y, как facecam и
ждёт. Слепишь смотрящей вбок — получишь в кадре картошку в профиль и не
поймёшь почему.

### Что требует наш загрузчик

`renderer.py` делает `trimesh.load(..., force="mesh")`, то есть схлопывает всё
в один меш. Отсюда требования:

* один объект, один материал, одна текстура;
* в материале Base Color должен быть **Image Texture**, а не просто цвет —
  иначе текстуры не будет;
* модификаторы применить (`Ctrl+A`) перед экспортом;
* скелет и анимацию можно не делать вовсе, они игнорируются.

### Если лепить не хочется

**Отсканировать настоящий предмет.** Meshroom есть в AUR (`meshroom-bin`), но
для плотной реконструкции он требует **CUDA**, а на Intel UHD 620 это не
заведётся. Рабочий путь — снять телефоном: современные сканеры отдают готовый
`.glb` или `.obj`, который останется подчистить в Blender.

**Сгенерировать кодом.** См. `tools/make_potato.py`. Для абстрактных форм —
овалов, комков, кристаллов — это быстрее любого редактора: поменял оси и
амплитуду, получил новый вариант за секунду. Скрипт годится как заготовка под
другую форму.

## Замеры

Этап 1, только трекинг (640x480, i5-8350U, без GPU):

```
кадров: 171 за 6.3 с  ->  27.3 fps
лицо найдено: 171/171 (100%)
трекинг: 20.1 мс/кадр
```

Разбор по стадиям в рабочем режиме:

| стадия | мс/кадр |
|---|---|
| трекинг (MediaPipe) | 23.0 |
| рендер 3D | 2.2 |
| маска вырезки | 5.6 |
| смешивание слоёв | было 27.2 → **стало ~0.9** |
| **композит целиком** | было 35.0 → **стало 7.8** |

Сквозной результат в режиме `avatar`, запись в виртуальную камеру:
**591 кадр за 20.0 с = 29.5 fps**. До оптимизации было 16.0 fps.

С картошкой и размытым фоном — те же **29.5 fps** (533 кадра за 18.1 с).

### Про размытие фона

Гауссово размытие ядром 61x61 по полному кадру стоило 9.2 мс и роняло частоту
до 25 fps. Заменено на уменьшение кадра в 6 раз, размытие маленьким ядром и
растяжение обратно — **1.27 мс**, на глаз неотличимо. Для сильного размытия это
всегда так: мелкие детали всё равно уничтожаются.

### Про смешивание

Первая версия делала два полнокадровых смешивания в float32 на 640x480x3 и
стоила 27 мс — вдвое дороже всего остального вместе, частота падала до 16 fps.
Исправлено двумя вещами: (1) всё считается только внутри ROI — прямоугольника,
накрывающего модель и вырезку, потому что остальной кадр не меняется;
(2) два последовательных смешивания раскрыты в одно.

### Про измерения

Первый замер рендера дал 20 мс и напугал. Это был артефакт: среднее по шести
вызовам, включая холодный старт (компиляция шейдеров, загрузка текстуры,
мипмапы). В установившемся режиме рендер стоит 2.2 мс, из них 1.7 — чтение
буфера из GPU в память. **Мерить только после прогрева.**

Трекинг устойчив: лицо не терялось ни разу, включая кадры с рукой перед лицом.
Поза шумит в пределах ~1.5° на неподвижной голове — сглаживание, скорее всего,
понадобится, но не срочно.

Запас по времени на кадр при 30 fps: 33 мс всего, из них трекинг съедает 20.
На рендер и композит остаётся ~13 мс. Если не уложимся — трекинг можно гонять
не на каждом кадре (поза меняется медленно), а рендер оставить на каждом.

## Утечка живого кадра (закрыто)

Первая рабочая версия при потере лица отдавала **сырой кадр с камеры**. То есть
стоило трекеру моргнуть — и в Teams уходило настоящее лицо и настоящая комната.
Для режима, весь смысл которого в том, чтобы тебя не было видно, это дыра, а не
мелкая недоделка. Поймано случайно: на контрольном снимке с виртуальной камеры
не оказалось ни картошки, ни размытия.

Закрыто в двух местах, где кадр мог просочиться:

* лицо не найдено (`facecam.py`) — отдаётся фон;
* голова почти в профиль, якоря глаз слиплись (`compose.py`) — отдаётся фон.

Счётчик потерянных кадров печатается при выходе, чтобы эта ситуация не была
незаметной.

**Правило на будущее:** любая новая ветка «что-то пошло не так» в режиме
`avatar` должна отдавать фон, а не `bgr`. Живой кадр — источник только для
глаз и рта, и больше никуда попадать не должен.

## Что известно кривого

1. **Модель не накрывает голову целиком** (актуально только для фона `real`).
   Торчат волосы, борода и подбородок. Лечится `--margin` побольше, но тогда
   рот уезжает из области модели: у Suzanne рот на выступающей морде, и
   расстояние глаза-рот не человеческое.
2. **Собственные глаза Suzanne** желтеют по краям вырезки. Больший `--dilate`
   закрывает их сильнее. У картошки этой проблемы нет — там глаз не было.
3. **Рот не привязан к модели.** Глаза совмещаются по якорям, а рот просто
   остаётся на своём месте в кадре. На картошке при `margin=1.6` он попадает
   куда надо, но у модели с другими пропорциями может уехать. Честный вариант —
   третий якорь для рта и перенос вырезки, а не только модели.
4. **Увеличение вырезки не компенсирует поворот.** Глаза масштабируются
   плоско, вокруг своего центра в плоскости кадра. При сильном повороте головы
   это чуть расходится с перспективой модели. На глаз незаметно, но это
   упрощение.
3. **Профиль.** При повороте головы под ~90° якоря сливаются в точку, размер
   модели взлетает. Сейчас кадр в этом случае просто пропускается
   (`fit_by_eyes` возвращает None) — видно настоящее лицо. Некрасиво, но
   безопасно.
5. **Дрожание.** Поза шумит на ~1.5° на неподвижной голове, модель слегка
   вибрирует. Сглаживание позы по нескольким кадрам не сделано.
6. **Свет.** Модель освещена фиксированным источником и не совпадает по
   освещению с комнатой.
7. **Шея и плечи** на однотонном фоне исчезают вместе с фоном — в кадре висит
   одна голова. Для картошки это скорее плюс, но если захочется тело, нужна
   сегментация человека, а это уже ML и заметный расход CPU.
